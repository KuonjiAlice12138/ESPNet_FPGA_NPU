# C/RTL Co-simulation OOM Investigation

## 1. Issue Overview
During the C/RTL co-simulation of the direct datapath (`execute_conv_datapath`), the `xsim` kernel crashes with a `FATAL_ERROR` (EXCEPTION_ACCESS_VIOLATION / OOM). The simulation memory usage peaks at approximately **10.7 GB (10747060 KB)** after running for nearly 2 hours.

## 2. Root Cause Analysis
The root cause of the memory exhaustion is the **massive transaction volume** generated by simulating the entire neural network frame in RTL.

In `tb/top_golden_sample_tb.cpp`, the core is invoked with `esp_int8::UOP_COUNT_ENCODER`:
```cpp
espnet_encoder_int8_core(frame_in, frame_out, param, esp_int8::MODE_RUN, esp_int8::UOP_COUNT_ENCODER);
```
`UOP_COUNT_ENCODER` is defined as `75`. This means the testbench forces the RTL simulation to sequentially process all 75 micro-operations (all layers of the encoder). 

By the time it crashed, the simulation had reached `72,203,145,100 ps` (72 ms), which corresponds to **7.2 million clock cycles** at a 10ns clock. The UVM AXI VIP (Verification IP) scoreboards, monitors, and memory models track every single read and write transaction across all AXI ports (gmem0, gmem1, gmem2, control). Over 75 layers, the queue size scales into the millions, eventually overwhelming the JVM/C++ memory allocator of Vivado Simulator.

## 3. Recommended Actions
To bypass the OOM and achieve a successful co-simulation, we must significantly reduce the XSIM memory footprint. 

### A. Use Single-Layer Debug Testbenches (Highest Priority)
Instead of `top_golden_sample_tb.cpp`, use the bounded debug testbenches (e.g., `dbg_u04_tb.cpp`, `dbg_u20_tb.cpp`). These testbenches use `DBG_STOP_AFTER` to halt the hardware after a specific number of micro-operations. 
```cpp
// From tb/dbg_u04_tb.cpp
#define DBG_STOP_AFTER 4
```
This restricts the simulated clock cycles and AXI transactions to a fraction of the full run, easily fitting into RAM.

### B. Disable/Reduce UVM Trace and Waveform Dumps
Ensure that in your `vitis-run` or Vitis HLS configuration (`hls_config*.cfg`), the `cosim.trace_level` is either omitted or explicitly set to `none`. Avoid `trace_level=all` or `trace_level=port` during full top-level simulations, as dumping huge `.wdb` / `.vcd` files exacerbates memory usage.

### C. Sub-module Co-simulation
Instead of verifying the entire `espnet_encoder_int8_core` top module, consider wrapping specific complex units (like `int8_core.cpp` or `sa_core.cpp`) in their own HLS testbenches and co-simulating them in isolation. This minimizes AXI VIP overhead and focuses testing purely on the datapath logic.
