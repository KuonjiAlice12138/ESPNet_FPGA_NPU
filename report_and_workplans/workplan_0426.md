### 1.2 FP32 平台信息补充了当前性能建模依据
今天重新阅读了 FP32 版硬件平台导出信息，重点确认了以下几项：

* 板级 `fabric_clk` 实际为 `~100 MHz`
* 旧版 4 路 AXI DMA 的 MM2S / S2MM 数据宽度与 burst 配置
* DDR / CCI / OCM 性能监视器的存在情况
* AFI 与 PS 侧内存互联配置痕迹

这些信息的价值在于：

* 进一步坐实了我们当前 INT8 `v1` 以 `100 MHz` 为首版验收频率是合理且现实的。
* 说明 FP32 路线原先的外部 DDR 数据通路实际上较窄，而 INT8 当前采用的“单 HLS 顶层 + `256-bit m_axi` 直连 DDR”是明确的架构升级。
* 同时也提醒我们：当前 C model 中的 DDR sustained efficiency 仍然属于经验参数，真正的最终置信度还需要等待新 INT8 HLS / Vivado 报告来校准。

### 1.3 资源与时序判断进一步收敛
今天重新核对了当前 final spec 的主要资源预算，结论没有变化，但置信度更高：

* `FMEM0/1/2` 固定后，总特征图片上缓存约 `9.25 MiB`
* `WBUF/QBUF` 固定走 BRAM
* `TM=32, TK=32`，首版固定不做 DSP packing

综合判断：

* 从纸面资源上看，当前方案在 ZU15EG 上没有明显超配问题
* 首版 `100 MHz` 是合理目标
* 真正的风险仍主要来自 URAM 使用密度和单顶层 dataflow 布线压力，而不是 DSP / BRAM 总量

因此目前可以认为：**100 MHz 下实现是有较大把握的，但最终仍需以第一版综合与实现报告为准。**

### 1.5 论文主线与轻量化策略完成一次收口
今天还重新对照了毕业论文中已有的剪枝与量化工作，并结合当前 INT8 NPU 的硬件规格重新评估了哪些内容适合继续作为论文主线。

目前得到的结论是：

* 当前论文主线不再强调“剪枝 + 多位宽量化”的并列叙事，而是收敛为“场景化轻量化 + 硬件对齐的对称 INT8 量化 + FPGA NPU 片上推理”。
* 毕业论文中的非结构化剪枝工作暂时弱化，不作为当前系统论文的主贡献。
* 在当前 INT8 版本 NPU 稳定测试通过后，再进一步考虑支持 `INT6 / INT4` 可选量化模式，把系统扩展为 reconfigurable accelerator。
* 对应地，后续需要重新收集一版与最终硬件模型对齐的不同目标模型量化测试数据，而不是直接沿用旧的量化实验口径。

## 2. 当前阶段结论

截至今天，INT8 NPU 项目已经基本具备进入 HLS 编码阶段的条件：

* final spec 已冻结并补充了模块映射关系
* 数据流、量化语义、调度和接口格式已经明确
* 性能模型初步表明在 `100 MHz` 下满足 `100 ms` 以内目标是有把握的
* 验证策略已经成形，后续可按 TB 分层推进
* 论文主线已收敛为以硬件对齐 `INT8` 为主、`INT6 / INT4` 为后续扩展的系统叙事

整体上，项目已经从“规格收敛阶段”进入“实现落地准备阶段”。

## 3. 下一步计划

下一阶段准备按以下顺序推进：

1. 开始编写 `espnet_encoder_int8_core` 的 HLS 骨架与顶层接口框架
2. 优先落地 `post_process_unit / concat_writer / avgpool_unit / window_generator` 等关键叶子模块
3. 搭建对应的单模块 testbench，并先完成 bit-exact 验证
4. 在叶子模块稳定后，再逐步搭建 `conv_domain_tb` 和 `top_tb`
5. 获取第一版 HLS 综合报告后，回填性能模型参数，进一步校准延时和时序风险判断
6. 并行整理当前硬件对齐 `INT8` 论文结果，补齐不同目标模型的量化测试数据
7. 在 `INT8` 路线稳定后，再规划 `INT6 / INT4` 可选量化模式的扩展验证

## 4. 小结

今天的工作没有再大规模扩展架构，而是围绕“把设计真正落到代码前需要补齐的最后几块内容”做了收尾，同时也把论文叙事从旧的轻量化实验口径切换到了更贴合当前硬件路线的版本。到目前为止，INT8 方案的规格、实现边界、验证路径、论文主线和实验边界都比前几天更稳，接下来工作的重心将转向 HLS 代码本身和与硬件对齐的量化结果整理。
